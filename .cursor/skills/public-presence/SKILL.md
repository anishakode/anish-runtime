# Public Presence

## Problem this prevents

Strong private constitution + weak public packaging → market underrates the engineer.

## Live product

- Prefer a real public URL once M26 (or approved staging) ships
- Do not imply ANISH // RUNTIME is live if it is not indexed/reachable
- Utility routes must work on the public site even if labs/AI fail

## GitHub profile

- Bio, location, and **website** link set
- Pin flagships only (e.g. MLOps, Steward_AI, Boring_AI) — archive noise unpinned
- Every flagship needs: description, topics, homepage (if any), **real README**

## Flagship README minimum

1. Problem / why it exists  
2. What is / isn’t claimed (evidence boundary)  
3. Architecture sketch  
4. How to run locally  
5. Tests / CI  
6. Links to sources / report  

Never ship a one-line README on a flagship.

## Identity hygiene

- Canonical email / LinkedIn / GitHub per handoff  
- Don’t surface obsolete emails or conflicting stale profiles in product copy  
- Devpost/other handles should not contradict canonical public identity when linked

## Honesty

Cursor/co-author tooling is fine; don’t hide it. Prefer clear `PORTFOLIO_EXTENSION` and prototype labels over inflated production claims.
