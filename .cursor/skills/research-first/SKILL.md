# Research First

## Rule

If a decision would change architecture, UX identity, evidence claims, AI behavior, or milestone scope:

1. **Ask the owner**, and/or  
2. **Deep-research online** (prefer Firecrawl search/scrape for current sources),

then propose options. Do not silently pick a trendy default.

Timebox research (enough to decide, not a literature review). Cite sources in the proposal. Prefer RUNTIME-native adaptation of principles over copying skins.

## Inspiration protocol (similar ≠ same)

Market portfolios often wow with 3D games, terminals, neon, or chatbot bubbles.

**Allowed:** extract the *job* of the interaction (proof-by-use, progressive depth, memorable first hit, shareable moment).

**Forbidden:** clone the costume (Bruno-style 3D nav, terminal-first UX, cyberpunk skins, chatbot-as-product).

### Translate table

| Principle | RUNTIME-native form |
|-----------|---------------------|
| Site proves skill | Labs + Source Trace + deterministic math |
| Strong first impression | RUN ANISH compilation (not particle theatre) |
| Conversational AI | Signal composes evidence UI (not chat-primary) |
| Playground | Project Autopsy lenses |
| Personalization | Consent Recompile + Ending Signal (session-only) |
| Shareable flex | Integrity manifests / journey seals |

## Research output format

```markdown
## Research brief
**Question:** …
**Sources:** (links)
**Patterns found:** …
**Anti-patterns to reject:** …
**RUNTIME-native options:** …
**Recommendation:** …
**Needs owner approval before:** …
```

## When to ask vs research

- **Ask owner:** identity, claims, email, evidence strength, milestone priority, legal/privacy.
- **Research:** libraries, a11y patterns, competitor UX principles, security baselines, deployment options.
- **Both:** anything that could become a WOW feature or public positioning.
