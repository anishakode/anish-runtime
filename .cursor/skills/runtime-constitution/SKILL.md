# Runtime Constitution

## What this is

An **executable professional identity**. Not a normal portfolio.

> Don't read what I can do. Run it. Break it. Inspect it. Challenge it. Trace the proof.

Design goal: **Make real engineering evidence feel unforgettable** — never “make ordinary claims look futuristic.”

## AI vs truth

| AI may | Software owns |
|--------|----------------|
| Interpret intent | Professional facts |
| Retrieve / summarize / arrange | Evidence states & strength |
| Constrained UI plans | Calculations, PSI/KS, sims |
| Extract JD requirements | Provenance, telemetry, session state |

> AI interprets the evidence. It does not become the evidence.

## Never become

- Normal résumé-only experience as the product
- Terminal-first UX
- Cyberpunk / neon hacker theatre
- 3D game / office navigation as primary UX
- Chatbot bubble as primary interface
- Arbitrary skill percentages
- Silent recruiter profiling / demographics
- Fit scores / hiring recommendations
- Fake infra metrics (K8s, OTel, FPS, uptime theatre)

## Non-negotiables

- Recruiter utility always available (see `recruiter-path`)
- Progressive enhancement: HTML → JS → visuals → AI
- Accessibility in architecture (keyboard, reduced motion, mobile semantic fallbacks)
- Session-bounded privacy; no persistent visitor dossiers
- Security: allowlists, bounds, rate limits, schema validation, server-only secrets, no arbitrary URL/shell/code from Signal
- Change control: new major ideas → backlog first; refine signature interactions before expanding

## When forced to choose

Provable claim > impressive claim · Improve existing signature WOW > new feature · Evidence integrity > AI autonomy · Recruiter clarity > futuristic chrome.

## Visual identity

**Digital Research Laboratory** — Editorial Lab (stories/CV) + Active Instrument (labs/Signal).  
Typography direction: Instrument Sans + IBM Plex Mono.  
Motion: nothing moves without semantic meaning (see `wow-craft`).
