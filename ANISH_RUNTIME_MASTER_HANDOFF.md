# 1. READ THIS FIRST — WHAT THIS PROJECT ACTUALLY IS

ANISH // RUNTIME is not intended to be a normal portfolio website.

It is an **evidence-first, AI-native, interactive engineering portfolio** designed to make Anish's professional capability inspectable and executable rather than merely described.

The central idea is:

> **Don't read what I can do. Run it. Break it. Inspect it. Challenge it. Trace the proof.**

A second formulation used throughout planning is:

> **Don't just tell people what Anish can do. Let them run it, break it, inspect it, challenge it, and understand how he thinks.**

The design constitution is:

> **Make real engineering evidence feel unforgettable.**

Never reinterpret that as:

> Make ordinary claims look futuristic.

The portfolio should feel like a **living engineering system representing Anish's professional identity through evidence, simulations, architecture, reasoning, runtime interaction, and adaptive presentation**.

The goal is not merely to impress visually.

The goal is for a visitor to be able to:

- inspect evidence behind claims;
- run bounded demonstrations;
- observe real deterministic calculations;
- intentionally break simulations;
- watch recovery/debug reasoning;
- trace an assertion to a source;
- inspect architecture;
- explore verified project relationships;
- ask natural-language questions over evidence;
- let AI interpret evidence without allowing AI to rewrite truth;
- temporarily reorganize the portfolio around relevant interests;
- map a job description against demonstrated evidence;
- generate interview questions from work the visitor actually inspected;
- inspect the architecture of the portfolio itself;
- finish with a reconstruction of their real exploration path;
- then reach Anish directly.

This is the core product idea and it must survive every future design, code, AI, infrastructure, or content decision.

# 7. MOTION CONSTITUTION

The motion rule is:

# NOTHING MOVES WITHOUT A REASON.

Motion must communicate something.

Approved semantic meanings include:

- node appears → information discovered;
- connection draws → relationship established;
- node moves closer → relevance increased;
- node moves away → relevance decreased;
- fade → de-emphasis;
- pulse → live activity;
- sharp disturbance → failure;
- travelling warning → incident propagation;
- layers separate → X-Ray inspection;
- network reorganizes → portfolio recompilation;
- light trail → visitor exploration;
- stabilizing movement → recovery.

The site must contain calm periods.

Constant movement weakens the meaningful moments.

The intended contrast is:

- Opening → controlled assembly;
- normal browsing → restrained;
- Break the System → dramatic;
- Failure Museum → quiet;
- Under the Surface → controlled reveal;
- Ending Signal → reflective.

Reduced-motion behavior must always exist.
